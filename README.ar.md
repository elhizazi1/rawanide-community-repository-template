# قالب مستودع مجتمع RawanIDE

هذا **قالب مستقل وفارغ**، ولا يتضمن إضافات جمال الحزازي أو أي حزم `.r1` منشورة مسبقًا.

## خطوات الاستخدام

1. أنشئ مستودع GitHub جديدًا باستخدام القالب، ثم استنسخه إلى هاتفك أو حاسوبك.
2. خصّص بيانات المستودع داخل `repo.config.json` → `repository`، ولا تحتاج إلى تعديل `owner` أو `repo` أو `branch` عند استخدام GitHub Actions.
3. استخدم [Extension SDK](https://github.com/elhizazi1/rawanide-extension-sdk) لتطوير إضافتك واختبارها محليًا.
4. انسخ **مصدر الإضافة** مع `manifest.json` والأيقونة إلى `extension-src/<name>/`، وأضف بياناتها إلى مصفوفة `extensions`.
5. شغّل `node tools/build.mjs` محليًا للتحقق من البناء وإنشاء `.r1` و`repository.json` والصفحات.
6. ارفع الملفات إلى GitHub؛ يقوم Workflow بإعادة البناء وتسجيل المخرجات المتغيرة.
7. يحاول Workflow تفعيل GitHub Pages تلقائيًا على `main` والجذر `/`. افتح **Summary** في سجل Actions لمعرفة النتيجة؛ إذا رفض GitHub التفعيل التلقائي، اتبع رابط الإعداد لمرة واحدة: **Settings → Pages → Deploy from a branch → main → / (root) → Save**. ثم اربط رابط `repository.json` مع Marketplace وفق آلية الإصدار المستخدم.

**مهم:** يبدأ المستودع دون إضافات؛ لا تُنشر أي إضافة إلا إذا أدرجها المطور عمدًا. لا تستخدم رمز تحقق خاصًا بناشر آخر. لا تعدّل حزمة `.r1` منشورة دون زيادة رقم إصدارها.

المشروع يعتمد على بنية البناء المستخلصة من مستودع مجتمع RawanIDE، مع فصل هوية الناشر عن القالب. يلزم اختبار النشر الفعلي والتوافق مع Marketplace قبل اعتباره إصدارًا نهائيًا.

[تطبيق RawanIDE](https://github.com/elhizazi1/RawanIDE) · [Extension SDK](https://github.com/elhizazi1/rawanide-extension-sdk) · [Marketplace](https://rawanide.elhizazi.me/repositories)

## الإعداد التلقائي عند إنشاء مستودع من القالب

- لا تحتاج إلى تعديل `owner` أو `repo` يدويًا: يتعرف GitHub Actions على الحساب واسم المستودع والفرع تلقائيًا. وعند التشغيل المحلي داخل نسخة مستنسخة يستخدم عنوان `origin`.
- يبدأ المستودع دون إضافات، ويعمل البناء حتى في غياب مجلد `extensions`.
- خصص بيانات العرض في `repo.config.json` ضمن `repository`، وخاصة `id` الفريد والاسم والناشر والوصف، قبل تسجيل المستودع في Marketplace.
- في إعدادات GitHub فعّل صلاحيات القراءة والكتابة لـActions إذا رُفض حفظ المخرجات، وإذا تعذر التفعيل التلقائي لـPages فاضبطه مرة واحدة على الفرع `main` والمجلد `/ (root)` حسب رابط Summary.
- لا يُعاد إنشاء Commit إلا إذا تغيرت ملفات البناء فعلًا.

## تشخيص النشر الأول

يحاول Workflow تفعيل Pages باستخدام رمز GitHub Actions المدمج، لكن بعض إعدادات GitHub وصلاحيات المستودع قد تمنع ذلك. نجاح البناء لا يعني بالضرورة أن الموقع منشور بالفعل. راجع **Actions → Summary**؛ ستجد رابط الموقع المتوقع ورابط إعداد Pages لمرة واحدة إذا لزم. بعد تفعيل Pages، تُنشر تحديثات الفرع `main` تلقائيًا.
