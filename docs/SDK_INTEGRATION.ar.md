# تكامل SDK 1.1.0

[English](SDK_INTEGRATION.md)

القالب يبني مستودع إضافات المجتمع، وSDK ينشئ الإضافات ويتحقق منها، وAPI Explorer يفحص بيئة المضيف ومصادر الإضافات المحفوظة داخل RawanIDE. لا يُضمّن SDK أو API Explorer في موقع المستودع.

| الرقم | معناه |
| --- | --- |
| SDK `1.1.0` | إصدار أدوات المطوّرين والقوالب وتعريفات الأنواع المستخدمة |
| Manifest: `apiVersion: "1.1"` | أقل API مضيف تحتاجه إضافة تستخدم بحث المشروع |
| Manifest: `apiVersion: "1.0"` | يظل صحيحًا للإضافات التي تستخدم الواجهات الأساسية فقط |
| Catalog: `protocol: "1.0"` | بروتوكول المستودع الحالي، لم يتغيّر |
| صيغة `.r1`: `1` | صيغة الحزم الحالية، لم تتغيّر |
| `version` في الإضافة | إصدار يحدده ناشر الإضافة، مستقل عن الأرقام الأخرى |

تثبيت SDK لا يحدّث تطبيق Android عند المستخدم. إعلان API 1.1 يجعل الإضافة تتطلب مضيفًا يدعمه؛ لذلك لا نرفع متطلبات إضافات API 1.0 دون حاجة، ولا نعدّل إصدارًا منشورًا أو نعيد تغليفه.

## التحقق والبناء محليًا

ثبّت SDK 1.1.0 باستخدام أمر npm أدناه. للتثبيت دون اتصال استخدم أرشيفًا محمّلًا مسبقًا بالأمر `npm install --global /path/to/elhizazi1-extension-sdk-1.1.0.tgz`. تحتاج بيئة CI إلى الوصول للسجل أو إلى أرشيف متاح لخادمها.

```sh
npm install --global @elhizazi1/extension-sdk@1.1.0
rawanide-sdk help
rawanide-sdk validate extension-src/my-extension --repository
rawanide-sdk audit extension-src/my-extension --repository
RAWANIDE_SDK_VALIDATE=1 node tools/build.mjs
node --test tools/tests/*.test.mjs
node tools/tests/verify-build.mjs
node tools/identity-guard.mjs
```

استبدل `my-extension` باسم مجلد إضافتك. يجب أن يتوفر SDK في PATH؛ وفي Termux استخدم أمر SDK المثبّت لبيئتك. يسمح `RAWANIDE_SDK_COMMAND` باختيار ملف تنفيذي آخر، وليس أمر shell يتضمن معاملات. عند التفعيل تستدعي أداة البناء `rawanide-sdk validate <source> --repository` دون shell؛ وفشل الفحص أو غياب الأداة يوقف البناء. يبقى تثبيت SDK اختياريًا عند عدم ضبط `RAWANIDE_SDK_VALIDATE=1`؛ وتبقى قواعد المجتمع والتحقق من الحزم المنشورة فعّالة، لكنها لا تستبدل فحص عقد المضيف الكامل.

ضع مجلدات المصدر في `extension-src/` وأضف ما تريد نشره إلى `repo.config.json` مع `src` و`releaseDate` و`changelog.en` و`tags`. تبني الأداة الحزمة وتسجل البصمة وتعيد استخدام الحزم المنشورة المطابقة دون تغيير بايتاتها. راجع معرّف الإضافة والناشر والترخيص والأيقونة والبيانات الإنجليزية والعربية قبل أول نشر. عند تحديث أدوات مستودع قائم احتفظ بهويته `repository.id` وحزمه وبصماته وروابطه وسجل إصداراته.

## التحقق الاختياري في CI

- GitHub: أضف متغير مستودع Actions باسم `RAWANIDE_SDK_VALIDATE` وقيمته `1` من Settings → Secrets and variables → Actions → Variables. يثبت سير العمل `@elhizazi1/extension-sdk@1.1.0` تحديدًا قبل البناء.
- GitLab: أضف متغير مشروع CI/CD باسم `RAWANIDE_SDK_VALIDATE` وقيمته `1`. يثبت عمل البناء الإصدار نفسه قبل التنفيذ.

لا يحتاج تثبيت حزمة npm العامة إلى رمز وصول. يجري القالبان اختبارات أدوات المستودع والتحقق من المخرجات. يبقى تثبيت SDK اختياريًا ومعطّلًا افتراضيًا. يحتاج تثبيته في CI إلى الاتصال بـ npm؛ ويجب التحقق من سير النشر على المنصة بصورة مستقلة عن الاختبارات المحلية.

## مثال بحث المشروع

المجلد `examples/hosted-js-project-search/` من SDK 1.1.0، مع أيقونة قابلة للاستبدال وترخيص وبيانات وREADME بالإنجليزية والعربية. وُضع خارج `extension-src/` ولم يُضف إلى قائمة النشر. انسخه إلى `extension-src/` فقط إذا أردت تطوير ونشر نسخة تخصك، ثم غيّر المعرّف والناشر وراجع الترخيص والإصدار قبل النشر.

يتطلب المثال API 1.1 وصلاحية `FILE_READ`، وصلاحية `UI_ACCESS` لعرض لوحة النتائج. تبحث `workspace.findFiles` عن الملفات المحفوظة، وتبحث `workspace.findText` عن نص حرفي في ملفات المشروع النصية UTF-8، بما فيها المغلقة. لا تبحثان في تعديلات المحرر غير المحفوظة، ولا تنفذان النتائج أو تفتحان واجهة البحث اليدوي أو تمنحان وصولًا عامًا إلى ملفات الجهاز. افحص `ok` والإلغاء والنتائج الجزئية والملفات المتجاوزة. راجع [عقد البحث العربي](workspace-search-1.1.ar.md) أو [الإنجليزي](workspace-search-1.1.md) الخاصين بإصدار SDK 1.1.0.

## فحص التطوير بواسطة API Explorer

استخدم تطبيقًا يدعم API 1.1 وثبّت الإضافة التي تطورها. يفحص قسم البيئة في API Explorer قدرات المضيف المتاحة. لفحص المصادر افتح مشروع الإضافة واحفظ التعديلات قبل الفحص. العثور على اسم دالة أو TODO هو فحص نصي ساكن؛ لا يثبت استيرادها أو تنفيذها أو نجاحها، وقد تتأثر الأعداد بالحدود والعناصر المتجاوزة. API Explorer ليس اعتمادًا في مستودعك ولا شهادة أمان، ولا يسجل القالب المستودع تلقائيًا في Marketplace.

للاختبار على الجهاز: ضع TODO معلومًا في ملف `.js` محفوظ ومغلق داخل مشروع تجريبي، وشغّل أمر المثال وتحقق من ظهور الملف في النتائج وتبديل اللغة بحسب لغة التطبيق. اختبر غياب المشروع أو الصلاحية عند الحاجة. اختبارات SDK والتغليف لا تعوّض هذا الاختبار الفعلي على المضيف.

## الملفات المشتركة وتطابق التغليف

ملفا `tools/community-rules.json` و`tools/lib/zip.mjs` مطابقان لقواعد SDK 1.1.0 وأداة تغليفه، وتُفحص بصمتاهما آليًا. عدّلهما في SDK أولًا ثم انقلهما إلى القالبين وحدّث اختبارات البصمات معًا. قواعد المجتمع أضيق من عقد المضيف: لا تسمح بـ `preview-js` أو الطرفية أو تشغيل العمليات أو صلاحيات الوصول العام لملفات الجهاز، وتتطلب بيانات إنجليزية وأيقونة موجودة.

لتشغيل اختبار التكامل مع SDK متاح في PATH:

```sh
RAWANIDE_TEST_SDK_COMMAND=rawanide-sdk node --test tools/tests/sdk-1.1.test.mjs
```

يفحص الاختبار الاختياري مصدري API 1.0 و1.1، ويقارن بايتات التغليف بين SDK وأداة المستودع، ويتحقق من توقف البناء عند رفض SDK للمصدر. عند عدم تعيين متغير أمر الاختبار تُتجاوز اختبارات الأداة الخارجية صراحةً، مع استمرار اختبارات البناء المحلية. تستخدم الاختبارات مجلدات مؤقتة ولا تنشر شيئًا أو تعدّل الإصدارات الموجودة.
